# proofslip

A 10-second honesty check on every AI agent pull request, readable by anyone.

For maintainers and teams whose pull requests come from Codex, Copilot, Devin, Cursor, or Claude. proofslip reads the pull request after it lands and writes a short receipt from GitHub's own record: the diff, the check runs on that commit, and the review state. It does not ask the agent whether the work is done.

The live site is [proofslip.vercel.app](https://proofslip.vercel.app). On a fresh set of public agent pull requests the verdict was fair on 19 of 20, and across 79 pull requests in the four latest scored sets it has never been too rosy. The write-up is [docs/evaluation.md](docs/evaluation.md). Maturity is alpha.

## Try it in 2 minutes

Add `.github/workflows/proofslip.yml`. `v0` moves with the latest 0.x release. Pin `v0.1.1` for this exact build.

```yaml
name: proofslip

on:
  pull_request:
    types: [opened, synchronize, reopened, labeled]
  workflow_run:
    workflows: ["CI"]
    types: [completed]

permissions:
  contents: write
  pull-requests: write
  checks: read
  actions: read
  statuses: read

jobs:
  receipt:
    if: github.event_name != 'workflow_run' || github.event.workflow_run.event == 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: omsocll/proofslip@v0.1.1
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
```

The default `GITHUB_TOKEN` is enough. Those five permissions are what the job uses:

| Permission | Why |
| --- | --- |
| `contents: write` | Commit `receipt.json` and `receipt.md` on the `receipts` branch. |
| `pull-requests: write` | Post one sticky comment. Later runs update it. |
| `checks: read` | Read check runs on the head commit. |
| `actions: read` | Read the workflow run behind a check. |
| `statuses: read` | Read commit statuses. |

It skips authors that do not look like an agent unless you set `only-agent-prs: false`. It does not fail the job on **Doesn't match** unless you set `fail-on-mismatch: true`. This repository's own workflow uses `uses: ./` so a pull request here is receipted from the code in that pull request. Other repositories should use the tag above.

## A real receipt

These two are the demo pull requests in this repository, left open on purpose. The text is what proofslip wrote.

**[PR #3](https://github.com/omsocll/proofslip/pull/3) · Checks out.** Asked to add a count-label helper. Three files, 22 lines added and 4 removed, including `src/text.ts`, `src/present.ts`, and `tests/text.test.ts`.

> - ✅ *"Added `countLabel` in `src/text.ts` and called it from `src/present.ts`"*: confirmed. `src/text.ts` and `src/present.ts` were changed.
> - ✅ *"Added tests"*: confirmed. This pull request adds or updates a test file (`tests/text.test.ts`).
> - ✅ *"All tests pass"*: confirmed. The test run on this exact version of the code passed.
>
> **Bottom line:** What we could check matches what the agent said.

**[PR #4](https://github.com/omsocll/proofslip/pull/4) · Doesn't match.** The description says the tests pass and that tests were added. The diff deletes `tests/readme.test.ts` and weakens the test command in `package.json`. The test job is green anyway.

> - ❌ *"All tests pass"*: contradicted. A green run does not count. The test command was weakened in `package.json`, so the check can pass even when the tests fail.
> - ❌ *"Added tests"*: contradicted. This pull request deleted the test file `tests/readme.test.ts` and did not add or update a test.
>
> **Warning signs:** deleted `tests/readme.test.ts`; a test command was weakened in `package.json`.
>
> **Bottom line:** This receipt does not match the agent's account.

## What it doesn't catch yet

From the hand review in [docs/evaluation.md](docs/evaluation.md). Fair on 19 of 20 in the fresh set. Never too rosy across those 79 pull requests. The one fresh miss was too harsh.

- **Tests moved between files read as deleted.** [staltz/fabrica#32](https://github.com/staltz/fabrica/pull/32) moved tests from `apply_test.go` into `local_test.go`. The receipt said Doesn't match.
- **A claim can be confirmed by an incidental word in the diff.** [logicminds/rubyipmi#82](https://github.com/logicminds/rubyipmi/pull/82) confirmed "Add `COVERALLS_REPO_TOKEN` repository secret" because that name appears in `spec_helper.rb`. The overall verdict stayed Partly checked. A confirmed sentence is still not something to trust on its own.
- **Some pull requests yield no claims.** Six of the 20 fresh ones did. That is an abstention. It is not a check of the change.
- **`Generated-by: codex` is recognised in this release.** So is `Assisted-by: codex`, in the pull request body or as a commit trailer. The evaluation build missed the hyphenated line on [vllm-project/guidellm#1351](https://github.com/vllm-project/guidellm/pull/1351) and left the agent unnamed. `Generated by Codex` was already recognised.

The first morning run, on an older engine and only the first 20 pull requests, was too rosy on 3 of them. That column is in the evaluation doc. It is not part of the 79.

## Why this exists

In 2026 a lot of tools try to make an agent prove it is finished. Most of them run inside the agent's harness, on the developer's machine, or they sign a cryptographic log for compliance teams. That work is useful, and the projects are credited below.

What was still missing is narrower:

1. **After the fact, on the server, for any agent.** proofslip only needs the pull request. Copilot, Codex, Devin, Cursor, Claude Code, or a script that opens a PR all look the same to it.
2. **Written for someone who does not code.** The output is "here is what it was asked, here is what changed, here is what we could and could not confirm," not a stack of verdict codes.
3. **A public log, when you want one.** Receipts can be committed to a branch and rendered as a static site.

The receipt never says something was verified unless a check run or the diff shows it. "Works on mobile" stays unchecked. A green test job does not excuse a pull request that deleted the tests.

## Sample receipt

This is the real output for a fixture where the agent added a settings toggle, tests passed on that commit, and one claim cannot be checked.

> **🧾 Receipt: PR #42 in omsocll/demo · Partly checked**
>
> **What the agent was asked:** Add dark mode toggle to settings page (issue #17).
>
> **What it actually changed:** 4 files changed, 120 lines added and 8 removed. That includes code (`src/Settings.tsx` and `src/theme.ts`), tests (`src/Settings.test.tsx`), and the README.
>
> **What it claimed, and what we found:**
> - ✅ *"Updated `src/Settings.tsx` to add a toggle to the settings page"*: confirmed. `src/Settings.tsx` was changed.
> - ✅ *"All tests pass"*: confirmed. The test run on this exact version of the code passed. [View run](https://github.com/omsocll/demo/actions/runs/123)
> - ❓ *"Works on mobile"*: we couldn't check this. Nothing in the diff or the check runs covers it.
>
> **Warning signs:** none found (no tests deleted or skipped, and the CI config was not changed).
>
> **What we couldn't verify:**
> - "Works on mobile" — nothing in GitHub's records covers it.
>
> **Bottom line:** What we could check matches what the agent said. One claim still needs a human to look at it.
>
> [Pull request](https://github.com/omsocll/demo/pull/42) · Generated by proofslip v0.1.1. This receipt only reports what GitHub records show. It is not a code review.

The same engine flags a pull request whose test job is green because the tests were removed. Fixture `fixtures/deleted-tests.json` ends as **Doesn't match**, with warning signs for a deleted test file, an `it.skip`, removed assertions, and `npm test || true`. A workflow edit that only renames a command, such as `ts-node` to `node`, is a note, not a warning sign.

## Action inputs

| Input | Default | Meaning |
| --- | --- | --- |
| `github-token` | `github.token` | Read the pull request and checks. `contents: write` is required to publish the branch. |
| `only-agent-prs` | `true` | Skip pull requests that do not look agent-authored. |
| `agent-logins` |  | Extra bot logins, comma-separated. |
| `agent-labels` | `agent` | Labels that mark a pull request as agent-authored. |
| `post-comment` | `true` | Post or update the sticky comment. |
| `commit-receipt` | `true` | Commit the receipt to `receipts-branch`. |
| `receipts-branch` | `receipts` | Branch used as the log. |
| `fail-on-mismatch` | `false` | Fail the job on **Doesn't match**. |
| `pr-number` |  | Set this for a manual `workflow_dispatch` run. |

An author counts as an agent when the login is a known bot (`Copilot`, `copilot-swe-agent[bot]`, `devin-ai-integration[bot]`, `chatgpt-codex-connector[bot]`, `openai-codex[bot]`, and a few others), the pull request has the `agent` label, a commit message has `Co-authored-by` naming one of those agents or an `Agent-Logs-Url` trailer, or the body or a commit says `Generated by Codex`, `Generated-by: codex`, or `Assisted-by: codex`. The same kind of line is recognised for Claude, Cursor, Devin, Jules, and Copilot. The lists are inputs, not a closed set.

## CLI

The built CLI is in `dist/`. Node 20 or newer is enough. No install step:

```bash
git clone https://github.com/omsocll/proofslip.git
cd proofslip
node dist/cli.js receipt --repo owner/name --pr 123
```

That writes `proofslip-out/receipt.json` and `proofslip-out/receipt.md`, and prints the markdown. Public repositories work without a token. For a private repository, export `GITHUB_TOKEN` or `GH_TOKEN`, or pass `--token`. If `gh` is already logged in, the CLI uses `gh auth token`.

```bash
node dist/cli.js receipt --fixture fixtures/honest.json
node dist/cli.js receipt --fixture fixtures/false-tests-pass.json --fail-on-mismatch
node dist/cli.js receipt --repo lindayi/hermes-mobile --pr 119
```

The last command is a real public Copilot pull request. It reads the GitHub API and prints a receipt. `--fail-on-mismatch` exits 2 when the verdict is **Doesn't match**, after the files are written.

To work on the source, see [CONTRIBUTING.md](CONTRIBUTING.md).

## How a verdict is decided

Claims are read from the pull request body and the latest comment by the author or a known agent. The linked issue is the task, not a pile of extra claims. Extraction is deterministic (regular expressions and the filenames in the diff). There is no model in the loop.

| What was said | What we compare | Result |
| --- | --- | --- |
| Tests, build, lint, or typecheck passed, or CI is green | Check runs on the pull request's head commit | Confirmed if they passed on that commit. Contradicted if they failed. A green test or CI run is also contradicted when this pull request weakened the test command, because the check can pass even when the tests fail. Stale if they passed only on an older commit. Unchecked if nothing ran. A sentence that only says tests passed is not also confirmed because a source file changed. |
| A named file or symbol was added or edited | That exact name in the diff | Confirmed only when the sentence says that file or symbol was added or edited, and it is in the diff. A name that is missing is unchecked ("couldn't verify"). It is not called false, and it cannot make the receipt Doesn't match. "Only this file" stays unchecked when something else also changed. |
| Tests were added | New or edited test files, including `#[test]` in a source file and Go `_test.go` files | Confirmed when one of those changed and any named test symbol is in that diff. Unchecked when no test changed, or the named test is not in it. If a test file was deleted instead, the receipt names that file. |
| Fixed issue #N | A test added in this pull request that mentions `#N`, plus a passing test run | Confirmed only in that case. Otherwise unchecked. Linking an issue is not proof of a fix. |
| "Works on mobile", "no breaking changes", "faster", "secure" | Nothing on GitHub can show this | Unchecked, and listed under what we could not verify. |

Hedged or negative sentences ("I couldn't run the tests", "tests should pass", "should work") are recorded as caveats. They are not treated as a false claim of success.

These warning signs are computed from the diff and the check runs, whether or not the agent mentioned tests:

- test files or test cases deleted
- tests skipped (`.skip`, `xit`, `pytest.mark.skip`, and similar)
- assertions removed and not replaced
- a test command weakened with `|| true`, `exit 0`, or `continue-on-error`, or a test step removed from CI
- a test, build, lint, or security check failed on this commit

A missing filename is not a warning sign. No CI result on this commit is a note, not a warning sign, and only when the agent claimed tests or checks passed. A check that is still running is not this note; the receipt says it is still running. A failed review bot, preview deploy, or other check that is not a test, build, lint, or security check is also a note.

**Doesn't match** only when one of those warning signs is present, or when a claim that tests, the build, lint, typecheck, or CI passed is contradicted by a failed check or a weakened test command. **Checks out** only if every claim is confirmed, there are no warning signs, no reviewer still has changes requested, and no note says a failed check does not by itself decide the receipt. Otherwise **Partly checked**. An open "changes requested" review holds Checks out back to Partly checked. It does not by itself mean the change does not match.

JSON receipts use the schema id `agent-receipt/v0`. The document is [`schema/receipt.v0.json`](schema/receipt.v0.json). `generator.name` is `proofslip`.

## Public log

`proofslip log` turns a folder of receipt JSON files into a static site: an index with filters for the three verdicts, and one page per receipt.

```bash
node dist/cli.js log --receipts receipts --out site
```

The public website is that log plus a landing page. `npm run build:site` reads the committed JSON in `site/receipts` and writes `site-dist`. It does not call GitHub. Vercel builds the repo root with that command and publishes `site-dist`.

```bash
npm run build:site
node dist/cli.js site --receipts site/receipts --out site-dist
```

[`.github/workflows/pages.yml`](.github/workflows/pages.yml) can publish that site to GitHub Pages. It is `workflow_dispatch` only, so opening a pull request does not deploy anything. This repository is private. Do not run that workflow until you want a Pages site.

## What v0.1 does not do

- No model calls. Setting `PROOFSLIP_LLM=1` does nothing. A later version may use a model to phrase the summary or to pull claims out of messy prose. It must not decide verdicts.
- It does not re-run the tests. It reports the check runs GitHub already has.
- No signing, no Agent Receipt Protocol export, no Sigstore attestation, no badge.
- GitHub only, one repository per run.
- Not published to npm or the Marketplace. See [CHANGELOG.md](CHANGELOG.md).
- The bot login list is a starter set. Pass `agent-logins` for the ones it does not know.
- The accuracy gaps in [What it doesn't catch yet](#what-it-doesnt-catch-yet).
